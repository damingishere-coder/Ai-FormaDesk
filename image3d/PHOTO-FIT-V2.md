# PhotoFit V2：阶段 A 实验接口

此分支实现照片约束、固定相机对照、参数化脚本和局部网格修正的实验闭环。
必须通过四个固定真实样本的机制验收后才进入网页集成。当前没有把 `photoFit`
暴露为可采用正式版本的生成 API，旧 `script` / `image3d` 行为不变。

## 执行

使用独立 `ZAOWU_DATA_DIR` 和现有 `FORMA_IMAGE3D_RUNTIME`。与视频、Blender 和
图生三维共用同一个推理锁，最多 30 分钟有效执行时间，两轮纠错，每轮最多三个问题、
两个力度候选。继续实验必须创建新目录，原记录不覆盖。

```sh
node --import tsx scripts/image3d/photo_fit_probe.ts controlled OUTPUT
node --import tsx scripts/image3d/photo_fit_probe.ts batch OUTPUT CONFIG_JSON
python scripts/image3d/photo_fit_report.py OUTPUT REPORT_DIRECTORY
```

批次配置是数组，每项含 `name`（唯一英文小写及连字符）、`reference`（透明 PNG）、
`strategy`（`mesh` 或 `script`）、`prompt`，网格路线还需要 `blend`。
所有路径均为本机实验路径，不写入作品数据库。公共样本使用原有 samples.lock.json，
猫咪图片不进入 Git。原图、底模和实际执行代码记录 SHA-256。

## 分阶段契约

- 照片约束：类别、策略及原因、可见部件/数量/置信度、关键点、表面特征、不确定区域。
  关键点经过蒙版检查，但没有可靠 3D 对应时不计入数值指标。
- 初始脚本：GPT 输出 Python，主要数字放在顶层字面量 `PARAMS` 字典。后台提供
  `fit.loft/sweep/repeat/leaf/boolean`，保存原脚本和实际执行的参数版本。
- 参数修正：仅允许已暴露的参数，每轮变动范围为当前绝对值的 35%（零附近最小范围
  0.025），整数参数保持整数。重新执行脚本后，在独立进程重新校验和渲染。
- 网格修正：最多三个平滑衰减的局部椭球形变。中心和半径基于冻结主体世界包围盒，
  单轴位移不超过 12%，缩放 0.65..1.35，半径 0.02..0.65；总位移不超过 18%。
  非目标对象、选区外顶点、UV、拓扑、对象变换保持不变。新增翻面/塌缩拒绝。
  模型必须从相机光线投射得到的编号锚点选择中心，不靠猜测世界坐标。也可选择
  最多五次、力度不超过 0.5 的局部邻接平滑；同样执行选区外不变与翻面检查。
- 数值门槛：目标误差至少改善 0.005，其他已有指标不得退化超过 0.002。局部修正
  同时检查固定相机下的投影区域轮廓误差与全局误差；不能用局部改善换全局退化。
  这组门槛是实验配置，不是主观质量百分比。
- 视觉门槛：将原照、修正后四面、修正前四面交给现有 Astra high 复核。退化或
  错把灰模当纹理错误时不采用。整体 `acceptable=false` 时仍可保留有改善的实验候选，
  但不能变成类别验收通过。

每个实验保存约束、相机搜索记录、冻结相机、逐轮方案、全/半力度候选、差异图、
完整 `.blend`、不超过 15 万三角面的 GLB、预览简化轮廓损失、实际耗时和进程组内存。
内存保护为 12 GiB，至少保留 10 GiB 磁盘空间。生成脚本不获得网络和外部文件权限；
渲染需要的系统缓存仅授予受信任渲染阶段。

## 验收边界与后续工作

受控测试必须恢复已知比例错误，同时通过共享网格隔离、选区外不变、非法输入、
参数替换与稳定 ID 检查。真实照片固定为现有建筑、椅子、盆栽和用户猫咪。
比较同一初始脚本的修正前后，以及原有底模的修正前后；历史底模的生成耗时单独报告，
不能冒充从照片开始的公平全流程计时。

三个以上样本出现有效改善才进入阶段 B。未过门槛时不展开完整 UI，不发布通用能力。
后续仍需：可靠 2D/3D 特征对应、辅助视角约束、带纹理修形拉伸检查与重烘焙、参数
作用范围与跨任务恢复、正式候选 API、关键点编辑 UI、五类各两图及旧渲染/视频回归。

参考方法：[Infinigen](https://github.com/princeton-vl/infinigen) 的程序化几何、
[LL3M](https://github.com/threedle/ll3m) 的脚本与视觉反馈。当前函数库为本项目原创，
未复制上游代码、安装其他模型或依赖 LL3M 演示服务；推理底模和纹理锁定清单不变。
