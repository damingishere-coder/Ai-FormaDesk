# 风格化 V2.1 阶段 A

当前为独立实验，不是正式作品精修 API；B/C 受四例及猫咪用户验收门槛约束。
现有 `script`、`image3d` 与 `photoFit` 行为不改，风格化实验记录使用 `route=stylized`。
默认圆润简化、轻度夸张，模型/登录不改，无新增下载。

## 可执行入口

使用独立 `ZAOWU_DATA_DIR`、现有 `FORMA_IMAGE3D_RUNTIME`：

```sh
node --import tsx scripts/image3d/stylized_probe.ts NEW_OUTPUT CASES_JSON
```

配置数组每项为 `{name, reference, prompt, budgetMs?, featuresFile?}`，`reference` 为本地透明PNG。
可选 `featuresFile` 仅复用原图 SHA256 相同的已验证特征记录；不同照片会拒绝。
输出目录不可已存在；单任务30分钟有效预算、最多两轮，每轮半/全力度均保留。
脚本生成的单次上限为15分钟，同时受当前剩余预算限制；其他阶段及旧路线保留既有上限。
没有付费模型回退或自动采用。失败、取消和超时保存已验证候选，不修改作品数据库。

## 分阶段契约

- `features.json`：5..10项核心特征，ID、部件、图片区域、可见性、置信度与检查方法；允许概括、省略和推测分开保存。
- 风格固定 `soft-simplified-v1`，圆润0.6、细节0.35；比例以照片分析为基准±15%。这是配置范围约束，不能证明GPT对照片基准的估计准确。
- Python 仅创建几何，字面量 `PARAMS` 与 `PARAM_RULES` 记录参数类别、绝对范围、照片基准与最终受影响部件名。参数搜索固定初始范围，不逐轮扩大。
- `sty.organic` 将椭球控制体块组合为平滑连续场，再通过有界采样与四面体等值面生成网格；控制点保存在对象属性中。`sty.ellipsoid/rounded_box/fuse` 提供其他体块与规则部件；`sty.surface_patch` 将浅眼部等形状贴合实际可见前表面，避免球眼外凸；`fit` 保留放样、曲线、叶片和受控布尔。融合只处理明确成员，眼睛、耳腔和薄叶需独立保护。
- 参数修改之后重新验证最终部件集合、ID、选定部件以外的坐标/拓扑/UV/变换/修改器/材质摘要（拓扑按有向顶点环、UV按同名顶点角规范化，允许无语义变化的面序排列），记录实际变化的部件；不允许以局部修改名义改变整个主体。
- 独立视觉契约检查核心特征、结构、风格、本轮目标改善和退化。中间候选在目标改善且无退化、文件和影响范围检查通过时可保留，不要求一次修正就达到整体质量标准。轮廓IoU仅诊断，不参与候选排名；两个力度都成功时优先半力度。最终通过要求至少三项可靠可见特征，且这些特征全部pass、整体结构和风格通过，预览轮廓损失不超过0.01。
- 上色为受信任JSON色板与椭球选面材质赋值，不执行AI材质脚本，不改变几何；前方-Y、Z向上。主色最多12色、32个主要花纹区域，输出标准GLB材质。光照明暗不作为纹理细节。
- 彩色检查使用中性环境补光。`stylized_relight_probe.ts EXPERIMENT_JSON NEW_OUTPUT` 可单独复核既有候选的检查照明，严格核对模型未变化并保留旧记录；该复核不算几何改善。
- 完整blend、预览GLB、灰模/彩色四面、冻结相机、脚本/参数、每轮理由与检查、SHA256和资源记录均保留。工作空间10GiB、进程组内存12GiB、重型阶段全局串行。

## 验收与未实现范围

四个固定样本为既有建筑、椅子、盆栽、猫咪，原图哈希保持一致。
阶段A需四例生成/保存/重新编辑/导出、至少三例通过特征风格结构检查、受控纠错与回退通过，且猫咪经用户认可。
`automaticPassed`只表示模型检查结果，`userAcceptance`保持pending直到真实用户反馈。

阶段B才接入正式候选、版本冲突、续修、特征编辑和网页入口。阶段C验证五类十图、图片/视频和完整浏览器回归。
本阶段没有实现自然语言改变比例边界、正式候选续修/采用、跨任务重启恢复、复杂纹理烘焙或用户认可的类别。

实验 CLI 的 `--overlap-analysis` 可重叠两例 Codex 分析；Blender 仍通过同一全局资源锁串行执行。每个样本独立计算有效预算。
