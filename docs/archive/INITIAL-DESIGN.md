# 造物工作台 · V1 开发文档

> 日期：2026-09-07  
> 状态：UI 方向已确认，待开发。本文档描述后续开发要求，不代表相关功能已经实现。  
> 目标平台：本机运行的桌面网页，优先适配 macOS Apple Silicon。

## 1. 产品目标与参考

开发一个面向建模新手的 AI 3D 工作台。用户在网页里描述需求，由本机 Codex CLI 编写 Python，后台 Blender 执行建模；用户也可以通过鼠标和参数面板直接修改模型。

核心流程：**描述需求 → AI 建模 → 网页预览 → 对话或手动修改 → 保存与导出。**

前端、后台、Blender 和项目文件都在本机；Codex 的 AI 推理仍需要联网。

## 2. 页面与功能

### 2.1 画布和鼠标操作

使用 Three.js 展示 Blender 导出的 GLB。

支持：

- 旋转观察、缩放、平移、适应模型大小。
- 透视、正面、侧面、顶部视角。
- 点击选中对象，显示轮廓与变换控件。
- 移动、旋转、缩放选中对象。
- 空白区域点击取消选择。
- 对象复制、删除和隐藏。

观察视角变化不修改模型。点击“渲染”时，使用当前观察视角生成 Blender 渲染图。

快捷键使用 `W` 移动、`E` 旋转、`R` 缩放；输入框获得焦点时不触发画布快捷键。

### 2.2 悬浮对话框

输入自然语言创建或修改场景，例如：

- “做一张木桌，桌上放一盏绿色台灯。”
- “把选中的台灯向右移动一点。”
- “给桌子增加一个抽屉。”

选中对象时，对话框显示对象名称，并把对应对象 ID 随指令提交给后台。

对话区展示 AI 回复和当前阶段：生成脚本、执行建模、更新预览、完成或失败。提供停止按钮；完整记录通过“对话记录”入口展开。

已按多模态创作升级：支持文字与 PNG/JPEG/WebP 参考图片共同讨论，文件选择、拖入和粘贴均可用；图片不是表面贴图。发送只讨论，确认方案卡后才建模。详细行为与验收见 docs/V2-ACCEPTANCE.md。

### 2.3 浮动属性面板

未选中对象时隐藏，选中后展示对应属性。

| 页签或对象类型 | 可修改内容 |
| --- | --- |
| 变换 | 位置、旋转、缩放 |
| 外观 | 基础颜色、粗糙度、金属感 |
| 灯光 | 颜色、强度；位置和方向沿用变换控件 |

第一版默认使用基础 PBR 材质、点光源和太阳光。复杂材质节点不提供完整网页编辑器。

调整选中对象的材质时，必要时复制共享材质，避免意外改变其他对象。

### 2.4 项目、历史与导出

- 项目可新建、重命名、切换和重新打开。
- 每次成功修改自动保存一个版本。
- 支持撤销、重做和历史版本恢复。
- 历史恢复后继续修改，会形成新的版本，不覆盖原历史文件。
- 导出当前已保存版本的 `.blend`、`.glb` 和 PNG。
- 渲染图标注其对应版本；场景更新后，旧图显示“需要重新渲染”。

第一版不包含顶点、边、面编辑、雕刻、骨骼动画、外部模型导入和多人协作。

## 3. 技术架构与数据一致性

### 3.1 技术选型

| 层级 | 选型 |
| --- | --- |
| 前端 | React、TypeScript、Vite |
| 3D 交互 | Three.js、React Three Fiber、Drei |
| 本地后台 | Node.js、TypeScript、Fastify |
| 参数与接口校验 | Zod |
| 项目和任务索引 | SQLite |
| AI 接入 | 本机 `codex app-server`，通过标准输入输出通信 |
| 建模与渲染 | Apple Silicon 版 Blender 4.5 LTS、Python |
| 状态推送 | SSE；操作通过 HTTP 接口提交 |
| 自动化验证 | Vitest、Playwright、真实 Blender 集成检查 |

开发期间使用 Vite；交付后由本地后台同时提供前端静态页面和接口，默认访问地址为 `http://127.0.0.1:8765`。

浏览器只访问工作台后台。后台负责连接 Codex、调度 Blender、登记版本以及提供产物，不能让浏览器直接执行 Python 或直接访问 Codex 控制接口。

### 3.2 Codex 接入

后台启动并管理工作台自己的 App Server 子进程，复用本机已有登录。官方协议支持对话、流式事件和审批等产品集成能力，见 [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。

- 使用 `gpt-6-astra`，默认思考档位为「高」`high`。
- 每个工作台项目关联独立 Codex 会话。
- 每轮提供最新场景摘要、选中对象、当前版本和用户指令。
- Codex 负责生成创建或修改场景的 Python；后台统一负责执行、验证和保存。
- 通过独立适配层处理协议，按本机 CLI 版本生成类型并做兼容检查。
- 不修改全局提供商、登录方式和模型配置。
- 第一版不启用子代理。

登录失效、额度不足或模型不可用时，暂停 AI 操作并给出明确提示；已保存模型仍可以查看和手动编辑。

### 3.3 Blender 执行

Blender 在后台运行，不要求用户打开其窗口。

创建任务从空白场景开始；修改任务读取最新成功版本的副本。

任务完成后必须产出：

- `.blend`：完整场景。
- `.glb`：网页预览模型。
- 场景清单：对象 ID、名称、层级、变换、材质、灯光和基础统计。
- 本次 Python 脚本及执行结果。

只有必要文件存在、可以读取，且场景清单校验成功，才能把任务标记为成功。PNG 渲染是独立任务，不阻塞模型保存。

### 3.4 网页与 Blender 同步

**以已保存的 `.blend` 为场景依据，网页 GLB 和场景清单为派生结果。**

- 为对象分配稳定 ID，保存到 Blender 自定义属性并导出到 GLB，不能仅凭对象名称匹配。
- 保留对象层级，统一处理 Blender 与网页的坐标轴、单位及变换转换。
- 鼠标拖动时先在网页即时展示，松开后提交一次修改；参数输入确认后提交。
- 手动修改由固定 Python 操作程序执行，不调用 AI。
- 新一轮 AI 操作必须等待手动修改保存完成，再读取最新状态。
- AI 对既有对象进行局部修改时保留其 ID；新增对象分配新 ID。
- 每次提交携带 `baseRevisionId`，后台拒绝基于旧版本的写入。

每个项目同一时间只执行一个场景修改。执行期间仍可观察模型，但暂停进一步编辑，防止修改互相覆盖。

网页实时预览与 Blender 渲染采用不同渲染器，不承诺像素一致。最终光照和材质效果以对应版本的 Blender 渲染图为准。

### 3.5 最小数据类型与接口

核心类型：

| 类型 | 主要字段 |
| --- | --- |
| Project | ID、名称、当前版本、Codex 会话 ID |
| Revision | ID、父版本、操作来源、生成文件、场景清单 |
| SceneObject | 稳定 ID、名称、类型、父对象 ID、变换、材质 |
| Job | ID、项目、基础版本、类型、阶段、错误、结果版本 |
| SceneCommand | 对象 ID、操作类型、参数、基础版本 |

任务状态统一为：`queued → running → succeeded / failed / cancelled`。

本地接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/health` | 检查后台、CLI 和 Blender 状态 |
| `GET/POST /api/projects` | 列出或创建项目 |
| `PATCH /api/projects/:id` | 重命名项目 |
| `GET /api/projects/:id/scene` | 获取当前场景和预览地址 |
| `POST /api/projects/:id/generate` | 发起 AI 创建或修改 |
| `POST /api/projects/:id/commands` | 提交鼠标、参数和对象操作 |
| `POST /api/projects/:id/render` | 渲染指定版本和当前视角 |
| `GET /api/projects/:id/revisions` | 查看版本历史 |
| `POST /api/projects/:id/restore` | 恢复历史版本 |
| `POST /api/jobs/:id/cancel` | 取消任务 |
| `GET /api/jobs/:id` | 查询任务状态和结果 |
| `GET /api/jobs/:id/events` | 接收任务进度 |
| `GET /api/artifacts/:id` | 获取预览或下载文件 |

文件接口只接受后台登记的文件 ID，不接受任意本机路径。

## 4. 保存、性能与故障处理

### 4.1 文件保存

每个任务在独立目录执行，成功后登记不可变版本，再更新项目当前版本。

SQLite 保存索引和状态，场景文件保存在本地数据目录。模型、日志、缓存和运行数据库不提交到 Git。

网页显示“已保存”必须以后台确认成功为依据。保存失败时，恢复上一成功版本并说明失败原因。

### 4.2 运行边界

- 服务仅监听本机地址，校验 Host、Origin 和本地会话。
- 使用参数数组启动进程，禁止把用户输入拼接成 Shell 命令。
- Codex 会话使用受限工作目录，阻止与建模无关的审批请求。
- Blender 执行进程不继承 Codex 凭据，使用 macOS 沙箱限制文件访问、写入目录和网络。
- 文件访问只允许任务数据、Blender 及其必要运行资源。
- 实施时必须真实验证沙箱限制；验证失败则停用生成执行，不自动放宽权限。
- 日志记录任务阶段和错误摘要，不记录认证信息。

### 4.3 M2、16GB 默认设置

- Blender 全局执行并发为 1。
- 预览使用 GLB 和网页实时渲染。
- PNG 默认使用 EEVEE，分辨率为 1280×720。
- 默认贴图上限为 2048×2048。
- 建模脚本超时 120 秒，PNG 渲染超时 180 秒，均可在本地设置中调整。
- 切换模型时释放旧纹理和几何资源。
- 第一版以单物体和小场景为主要验收范围，不承诺固定渲染速度。

### 4.4 失败恢复

- Python 错误自动回传 Codex，最多修复两次，仍失败则保留原版本。
- 用户取消时停止对应任务进程，废弃未完成输出。
- 后台重启后，将中断任务标记为失败，不自动重跑 AI 指令。
- SSE 断开后允许重连，并从后台重新获取任务最终状态。
- 版本冲突返回明确错误，前端重新读取当前场景，不覆盖。
- Blender 缺失、路径错误或 CLI 不兼容时，在启动检查页展示处理入口。

## 5. 实施顺序与验收标准

### 5.1 阶段一：真实生成与网页预览

建立前后端基础、启动检查和任务系统，完成：

**网页输入 → Codex 生成 Python → Blender 建模 → GLB 展示 → 保存与导出。**

同时按已确认概念图实现大画布和悬浮对话框。

### 5.2 阶段二：网页编辑与一致性

实现选中对象、变换控件、属性面板、场景列表和版本保存。

优先验证“网页修改能够写回 Blender”，然后加入撤销、重做和历史恢复。

### 5.3 阶段三：渲染与交付

补齐渲染预览、取消、失败恢复、完整导出和 Mac 双击启动入口。

启动入口只启动工作台及其子进程，不自动更新 Codex 或修改登录配置。

### 5.4 必须通过的验收场景

1. **首次生成**：输入“木桌和绿色台灯”，网页显示实际 Blender 输出的模型，导出的 `.blend` 能正常打开。
2. **手动编辑**：移动台灯、旋转对象、缩放桌子并修改颜色。刷新网页和重新打开 `.blend` 后，修改均保留。
3. **继续对话**：完成手动修改后要求“增加一个杯子”，原有位置和颜色不被重置。
4. **选择与属性**：对象选择、轮廓、属性面板和对话对象上下文保持一致；同名对象也不会误选。
5. **版本恢复**：撤销、重做、恢复旧版本后，网页、导出文件和后续 AI 操作使用同一版本。
6. **渲染**：PNG 使用提交时的场景版本和观察视角；场景改变后正确标记旧渲染图。
7. **异常处理**：验证脚本错误、任务取消、进程中断、未登录、Blender 缺失、旧版本提交和连接重建。
8. **执行限制**：测试越界读取、越界写入和网络访问被阻止；异常任务不能损坏已有版本。
9. **视觉与浏览器**：在本机 Chrome 中检查 1536×1024 和 1280×800 布局，确认浮动面板不遮挡主要操作，画布和文本输入快捷键互不干扰。

最终验收必须包含真实 Codex 调用、真实 Blender 执行和浏览器操作。模拟接口、静态图片或仅构建成功，都不能代替完整流程验收。
