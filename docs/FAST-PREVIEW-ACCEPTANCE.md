## 实现

- `blender/portable.py`：固定材质数值与支持的图片连接直接导出，只烘焙无法直接导出的通道。保留材质槽、发光等未处理通道。
- 小部件使用 512、主要部件使用 1024；本例为 35 个 512 和 101 个 1024。只影响预览贴图，原始 Blender 文件保留。
- 缓存按完整模型文件内容、Blender 版本、转换代码版本、对象 ID、通道和分辨率区分；不按材质名称盲目共用。每张完成贴图单独记录。
- `server/jobs.ts`：先保存基础版本，再排队生成预览细节。预览失败不撤销基础版本；继续任务复用贴图。用户发起有效的新操作可中断旧预览，晚到结果不能覆盖新版本。
- 已经产出 raw.blend 的无图生成任务重试时，复制已有模型并继续校验/导出，不重新执行 generated.py，也不要求 AI 在线。
- 校验阶段失败仍提供已生成模型的下载入口。进程超时或取消时保留已收集的日志。
- 界面显示“生成基础预览”“已保存 · 基础预览”和“继续生成预览细节”；终态不会显示重新连接。旧任务事件与迟到的快照不能覆盖新任务。
- 使用 glTF-Transform 仅处理纹理去重和无损 WebP；不使用合并对象、简化几何等优化。压缩收益有限，本例仍约 127–129 MiB；完整贴图的 GPU 内存占用没有因 WebP 而消失。

## 验证与限制

- 53 项 Vitest 测试通过，包含原始模型恢复、细节失败保留版本、断点恢复、旧版本保护、压缩像素与对象结构不变。
- 浏览器测试覆盖预览失败重试、快照刷新失败、旧预览事件与新任务竞态；现有创作浮窗布局测试通过。布局夹具补齐了既有 Blender 状态请求。
- 两项真实 Blender 回归通过：修改粗糙度后木纹颜色像素不变、未编辑对象的材质/几何/变换不变、未授权变换被拒绝；图像材质编辑后实际红色条纹保留，粗糙度 0.6 生效，三个区域光保留。验证改为检查目标材质引用与像素，不再把冗余贴图数量当作质量指标。
- 生产构建与 TypeScript 检查通过。已有前端大包提示仍在。
- glTF-Validator：基础预览 0 错误、0 警告；完整预览 0 错误、136 条运行时生成切线空间提示。当前 Three.js 页面已检查；其他查看器可能有凹凸细节差异。
- 尚未采用任意 Blender 着色器到网页着色器的通用转换；分类与视觉对比仍应随新增材质类型扩展。

复现断点恢复、缓存和场景一致性：

```sh
./node_modules/.bin/tsx scripts/verify-preview-fast.ts <已保存模型.blend>
./node_modules/.bin/vitest run
./node_modules/.bin/playwright test tests/browser/preview-progress.spec.ts tests/browser/composer.spec.ts --reporter=list
```

验证脚本在独立 `data/preview-check-*` 目录运行，不覆盖输入模型。
